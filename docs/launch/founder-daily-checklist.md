# Founder Daily Checklist — Validation Phase

Use this during the 14-day validation period.

## Before development

- [ ] Review yesterday's completed tasks, failures, and cost.
- [ ] Confirm the remaining daily model and cloud budget.
- [ ] Identify the single validation question for today.
- [ ] Confirm that today's work strengthens the AI browser product, not only the shopping demo.
- [ ] Reject work that does not improve browser comprehension, public demo quality, measured task economics, U.S. user evidence, or a concrete credits/commercial outcome path.

## Positioning check

- [ ] Describe the product first as an AI browser.
- [ ] Describe the user value as searching, comparing, and completing web tasks with explicit control.
- [ ] Describe laptop shopping as the first validation wedge, not the product category.
- [ ] Describe “selling results” as the business model, not the user-facing product.
- [ ] Do not use “shopping assistant,” “affiliate platform,” or “results marketplace” as the primary product description.
- [ ] Confirm that no copy implies paid ranking, private browsing-data sales, or automatic high-risk execution.

## During development

- [ ] Use fixtures for UI work.
- [ ] Do not run paid model calls during styling, routing, or ordinary component tests.
- [ ] Keep one primary reasoning call as the default comparison ceiling.
- [ ] Keep browser-level task state separate from shopping-specific data structures.
- [ ] Preserve ordinary Search fallback.
- [ ] Record every external-data and model dependency.
- [ ] Add a fallback for budget exhaustion and provider failure.

## User validation

- [ ] Recruit or schedule at least one U.S. participant.
- [ ] Observe without explaining the interface.
- [ ] Record whether the participant understood that the product is a browser for search and tasks.
- [ ] Record whether Search, Compare, and Prepare were understood.
- [ ] Record whether the recommendation and Sponsored distinction were understood.
- [ ] Record whether the participant preferred ordinary search.
- [ ] Record task outcome, handoff, failure, and cost.
- [ ] Write one sentence describing the most important browser or trust confusion.

## Commercial validation

- [ ] Research or contact one relevant merchant, provider, affiliate, developer-platform, or strategic partner.
- [ ] Ask what result they pay for and how they define success.
- [ ] Record attribution, reversal, data, and payment requirements.
- [ ] Reject any path that requires paid influence over independent ranking.
- [ ] Reject any path that requires unnecessary private browsing data.

## Credits and fundraising

- [ ] Complete or improve one startup-credit application item.
- [ ] Research one highly relevant browser, consumer AI, search, infrastructure, commerce, or marketplace investor or accelerator.
- [ ] Send no more than a small number of personalized messages.
- [ ] Keep AI browser first, first wedge second, business model third in every message.
- [ ] Do not report unmeasured traction or live capabilities that do not exist.

## End of day

- [ ] Record total spend and completed, abandoned, and failed tasks.
- [ ] Calculate cost per completed task and cost per Prepare handoff.
- [ ] Update expected commercial value and gross contribution per 100 tasks only when supported by evidence.
- [ ] Decide whether the day's work changed the browser, investment, or commercial decision.
- [ ] Stop paid experimentation when the daily budget is reached.
